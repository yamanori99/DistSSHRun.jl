API

Exported names, grouped by the command they belong to. The longer guide is the DistSSHKit manual.

Run

go! runs a script as-is on one or more slots. drive! runs a driver script on workers. ride! is experimental: it rewrites map and filter in a script onto workers.

DistSSHRun.DriveHostStatus — Type

Live per-host membership during a drive (not the post-run collect outcome).

state is :joined, :alive, :left, or :collect_pending. last_seen is Unix time when this host last appeared in Distributed.workers(), or nothing if it has not been observed since join.

DistSSHRun.DriveResult — Type

Outcome of drive! (and similar CLI steps that return an exit code).

ok is true only when the run finished with exit 0. By default that includes the placement contract: listed parent / child hosts joined, stayed, and collect succeeded (require_all_hosts=true). require_all_hosts=false keeps a partial run as ok=true.

output_dir / log_dir are the directories actually used for this run — resolved the same way drive reports Results: / writes its log, even when drive! was not called with output_dir= / log_dir=. nothing when no real run happened (e.g. built by hand) or, for log_dir, when logging was disabled.

hosts is one HostRunResult per host that joined as a worker, in the order results were collected. Empty when no host-collection step ran (e.g. built by hand, or a run with no remote/local-only hosts).

run_dir is this run's DISTSSHKIT_RUN_DIR when the driver allocated one. Read it with result_run_dir. result_provenance reads run.toml from it. result_content_tree_hash and result_remote_run_id read provenance.shipped in that file.

Result fields and positional constructors are not API. Result structs are not a stable serialization format. serialize and JLD2 of a result are unsupported. The supported record is kit.result.

DistSSHRun.HostRunResult — Type

Per-host outcome of the drive result-collection step.

ok is false when SSH / find / rsync raises while collecting from host. An empty file list after a successful probe is not an error. error is the message string, or nothing on success. An AbstractString is stored as-is so kit.result round-trips; other values use sprint(showerror, error).

DistSSHRun.KitProcess — Type

Handle to a detached execute! child (detached=true).

process is the julia -m DistSSHKit go|drive|ride subprocess. run_dir is always allocated in the parent before spawn (pid / kit.out / run.toml). Read it with result_run_dir. The field is not API. output_dir is the artifact root when known at spawn (go / ride, explicit output_dir=, or inherited DISTRIBUTED_OUTPUT_DIR). Detached :drive without those leaves output_dir as nothing so the child can honor init_output_dir!. log_dir is nothing for :go / :ride. wait returns a KitRunResult; it does not fill output_dir on this handle.

source
DistSSHRun.KitRunResult — Type

Shared run outcome (ok, kind, dirs, failed_step, exit_code, hosts, stop).

kind is :go, :drive, :ride, or :pipeline. Convert with kit_run_result. hosts is post-run collect (HostRunResult); empty for go, hung wait, or a drive that never collected.

stop is the terminate! / terminate_run! ladder outcome. nothing on a run that was not stopped that way. :within_grace means one SIGINT was sent and the process was gone before SIGTERM, so workers had that interrupt_grace window. :sigterm and :sigkill mean that window ended and the ladder escalated. :no_sigint means interrupt_grace was 0, so SIGINT was not sent and the ladder went to SIGTERM (then SIGKILL if the process was still alive). The same string is stop in kit.result. When the kit run directory already has this package's run.toml, stop is set there too. schema stays 1. An unknown stop string is ignored.

run_dir is this run's DISTSSHKIT_RUN_DIR when one is known. Read it with result_run_dir. result_provenance reads run.toml from it. result_content_tree_hash and result_remote_run_id read provenance.shipped in that file. A RideResult is not accepted there; convert it with kit_run_result first.

Result fields and positional constructors are not API. Result structs are not a stable serialization format. serialize and JLD2 of a result are unsupported. The supported record is kit.result.

DistSSHRun.drive! — Method
drive!(session::KitSession, script; plan=nothing, args=[], ...)
drive!(script, workers...; kwargs...)
drive!(script, workers::AbstractVector; kwargs...)

Run a driver script on workers. Tokens match the CLI (parent:2, child:user@host:1). Load is the master include. Publish sends definitions to workers (not top-level work). Run is main() when defined. Use go! / ride! when that matches the script.

drive!("job.jl", "parent:2"; args=["8"])
drive!(session, "job.jl")  # uses `session.tokens`

With sync omitted or false, prepare remotes with setup! or CLI setup first; remotes are checked before execution. Optional sync=:sync / sync=:ship_tree copies, then checks. After :ship_tree, hosts that still lack Manifest deps get instantiate! (same as CLI drive --ship-tree). Git parity is off by default (skip_hash_check=true). With sync=:ship_tree, parity stays off even if skip_hash_check=false (no remote .git/). require_all_hosts=true (the default; CLI --require-all-hosts) fails unless every explicit parent:N / child:NAME:N joined, stayed through the run, and collect succeeded. Pass require_all_hosts=false or CLI --best-effort for a partial run.

A collect root that is the project or a parent of it stops the run before main and before collect, with exit code 1. That includes DISTRIBUTED_COLLECT_DIRS and a default root from DISTRIBUTED_OUTPUT_DIR.

mem_headroom / parent_gb are the RAM budget for drive preflight (same as size! / CLI --mem-headroom / --parent-gb). pipeline! passes config.mem_headroom and config.parent_gb.

julia sets the remote Julia binary (nothing / "auto" → detect; same as CLI --julia). plan is an optional explicit WorkerPlan. pipeline! syncs separately and does not pass sync= into drive!, so it does not instantiate after rsync.

sync_script=true (CLI --sync-script) re-includes the full driver on workers. The default publishes definitions / using / import / include only, so top-level work on Load is not repeated on workers.

Ctrl-C restores the active project and the DISTRIBUTED_* entries this call changed, then rethrows InterruptException or, when Julia has it, Base.CancellationRequest. drive! does not exit and does not throw the private CLI exception. On Julia 1.14 the caller's task stays cancelled after that exception.

DistSSHRun.go! — Method
go!(script, workers...; kwargs...)
go!(script, workers::AbstractVector; kwargs...)

Run an as-is complete job on one or more slots (local and/or remote).

[provenance] records this controller under julia.parent and machine.parent. Each slot that ran the script is under workers, grouped by placement token. The manifest hash and the git snapshot are taken when go! starts.

go!("job.jl")                          # one parent slot
go!("job.jl"; repeat=100)              # 100 independent runs on parent
go!("job.jl", "parent:2"; args=["8"])
go!("job.jl", "child:user@h1:1", "child:user@h2:1"; remote="/path/to/project")

Each slot gets DISTRIBUTED_OUTPUT_DIR pointing at {script}/.distsshkit/go/<stem>_<UTC>/<slot>/. Override the batch root with output_dir (CLI: --output-dir). For backward compatibility collect_spec::AbstractString also sets the batch root, but passing both output_dir and collect_spec::String is an error. collect_spec === false means "skip collect" and is orthogonal to output_dir.

Default sync is false (no pre-run sync; remotes are checked first — setup is assumed done). Pass sync=:sync or sync=:ship_tree to copy, then check. After :ship_tree, hosts that still lack Manifest deps get instantiate! before the check. go! has no git-parity gate; use drive! with skip_hash_check=false (CLI: drive --require-git) when you need that.

julia sets the Julia binary for each slot (nothing / "auto" → detect; same as CLI --julia).

allow_mismatch (CLI --allow-mismatch) waives Julia version / commit, DistSSH* Manifest versions, and/or Manifest path when a slot does not match the job tree. Default is to error. Same tokens as drive / ride: julia, distssh, manifest.

When workers is empty and hosts_file is omitted, DISTSSHKIT_HOSTS_FILE is still read (API go!("job.jl")). Non-empty workers (CLI host_tokens) does not re-read that ENV.

parent:N and child:NAME:N mean N independent full-job runs (not Distributed workers), started together. repeat=N (CLI --repeat N) is the total number of those runs, spread round-robin across listed hosts (no tokens → all on parent). :N on a token is a per-host cap when repeat is set; omit it to leave that host uncapped. Without repeat, every listed token needs :N (omitting it is not 1 and not size!). Empty tokens stay one parent slot. path_anchor shortens displayed paths (CLI passes kit project root).

DistSSHRun.ride! — Method
ride!(script, workers...; args=[], spi_check=false, output_dir=nothing, project=pwd())

Experimental. Rewrite map / filter / simple comprehensions / independent indexed for (dest[i] = …) and run the script on Distributed workers (parent and optional SSH child:). Rejects Distributed vocabulary (use drive!).

Worker add for SSH children is the same add_drive_workers! path as drive. The job project is Pkg.activated on the parent first (drive does this before using the app package on every process). The script still runs on the parent (no driver include on workers). Named functions used by map / filter are sent to workers as a prelude.

--spi-check (default off) compares the distributed result to a sequential map / filter. Unknown syntax stays sequential. Listed child: hosts are fail-closed (require_all_hosts=true). Queue: execute! :ride (detached=true writes kit.result like go; SSH child: also writes kit.hosts for terminate!).

DistSSHRun.terminate! — Method
terminate!(kp::KitProcess; grace=10, interrupt_grace=nothing) -> KitRunResult

Stop a detached run. Omit interrupt_grace and the wait is 30 seconds, or DISTSSHKIT_WAIT_SIGINT_GRACE when that variable is set in this process. The driver host does not read it. An explicit interrupt_grace keyword wins, including 0, which sends no SIGINT. A negative value or NaN is an error. The 30 second default is a constant, chosen from the internal stop budgets, not computed when terminate! runs.

A positive value sends SIGINT once and waits that many seconds. There is no retry. A drive child runs its Ctrl-C path: one kill -INT per SSH host, aimed at the worker julia pid (WorkerConfig.ospid, the worker's getpid()), then a fixed 3 second settle, then rmprocs. That ssh is bounded by the SSH connect timeout and uses ServerAliveInterval=5 and ServerAliveCountMax=1. A write during the settle window is best-effort and should be small. Checkpoint large state during the run, to a temporary file, then rename it. A 1 GiB write in 0.4–0.7 seconds on one Mac mini is a lower bound. On Julia 1.13 a second Ctrl-C forces the driver out of that cleanup. On Julia 1.13, a driver waiting in pmap ignores SIGINT, so this wait runs out and SIGTERM stops it. With the defaults that is 30 seconds plus grace (10) plus one second after SIGKILL, about 41 seconds, and then the tagged pkill below. A process-group SIGINT, as from a terminal Ctrl-C, also misses that path on Julia 1.13: the driver exits 1 and does not send kill -INT. Measured on macOS. On Julia 1.14 the driver exits 130, but a worker can be removed before it sees the interrupt. A go or ride child is julia -m with exit-on-sigint, so SIGINT runs atexit and does not enter catch or finally. Then SIGTERM, wait up to grace seconds (0 sends SIGTERM and does not wait), then SIGKILL if the process is still alive. Then pkill only processes tagged with this run's job_id (from kit.job), never julia.*--worker. Without job_id, only the child is signaled. That pkill is one SSH command per host, in parallel, deduplicated, with its own 15 second bound (SSH connect plus margin). It does not spend interrupt_grace. Worst case for those two stages is interrupt_grace plus that bound. pkill exit 1 means nothing matched and is success. Hosts that cannot be reached are named in one warning, and this still returns. The remote pattern is [d]istsshkit-job:…, so pkill -f does not match the sh -c line that contains the command.

The returned KitRunResult stop is that ladder outcome. The same string is written to kit.result. When run_dir holds this package's run.toml (schema = 1, writer starting with DistSSHRun), stop is set there too. Artifact output_dir / log_dir are not rewritten.

DistSSHRun.terminate_run! — Method
terminate_run!(output_dir; grace=10, interrupt_grace=nothing, log_dir=nothing, kind=:go) -> KitRunResult

Like terminate! after losing KitProcess: read kit.pid / kit.job / kit.hosts under output_dir. interrupt_grace is the same SIGINT stage, including the 30 second default and DISTSSHKIT_WAIT_SIGINT_GRACE in this process. kind is only used when kit.result is missing. stop is the ladder outcome, including on that synthetic result. run.toml is stamped in the kit run directory named by kit.run_dir next to kit.pid, or in output_dir when that directory already holds this package's run.toml.

Base.wait — Method
wait(kp::KitProcess; timeout=nothing) -> KitRunResult

Block until the detached child exits, then return a KitRunResult.

Does not mutate kp.output_dir / kp.log_dir. After a detached :drive that deferred the artifact leaf, read the returned result (or kit_result_from_dir / read_kit_run_toml on the directory from result_run_dir).

timeout is wall-clock seconds until the child process exits (not the drive worker heartbeat). nothing waits forever. On timeout the child is left running: failed_step is "hung", exit_code is 124, and owned stdio stays open. Call terminate! if the hang is fatal.

If the child wrote kit.result under run_dir or output_dir, that file is the source of truth (including failed_step from go! / ride!). Otherwise failed_step is "go" / "ride" / "drive" on a non-zero exit — the parent cannot recover a more specific in-process step name.

Best-effort: remove kit.pid if it still names this child (pid captured before wait on the OS process; after reap getpid can throw ESRCH). Not on a hung timeout.

DistSSHRun.instantiate! — Method
instantiate!(session::KitSession; julia="auto") -> SyncResult

Run Pkg.instantiate on each SSH host in session (parallel).

The worker stops, and names help setup, when it has no reachable registry, when Pkg.is_manifest_current is not true (a Manifest with no project_hash counts), or when Manifest julia_version is missing or its minor differs from that Julia. Otherwise the worker runs Pkg.instantiate(; manifest=true, update_registry=false, julia_version_strict=true).

julia is the remote Julia path ("auto" detects per host, same as setup --instantiate / drive --julia). Returns SyncResult.

Typical first-time remote prep:

session = KitSession(workers=["child:user@h1"], remote="/path/to/project", yes=true)
setup!(session, :ship_tree, :instantiate)  # or sync!(…; mode=:ship_tree) then instantiate!

Also available as setup!(session, :instantiate; julia=…).

DistSSHRun.sync! — Method
sync!(session::KitSession; mode=:sync)

Sync local project to SSH hosts (call explicitly; go/drive do not call this by default).

  • mode=:sync — push the local branch to origin, then check out that commit on each remote as a detached HEAD (confirm unless session.yes). Does not run git pull. A dirty tree is refused.
  • mode=:ship_tree — pack the project (each directory's .gitignore) into a tar and extract under runs/<run_id>/src/ (confirm unless session.yes).

Returns SyncResult. For :ship_tree, result_content_tree_hash and result_remote_run_id read that ship. Other modes return nothing.

A regular file is the SHA-256 of its bytes. DistSSHRun.execute! — Function
execute!(kind, script, tokens=String[]; output_dir=nothing, args=String[], project=pwd(), sync=nothing, julia=nothing, detached=false, source=nothing, kwargs...) -> KitRunResult or KitProcess

One seam over go! / ride! / drive! for callers that pick the kind at runtime (kind ∈ (:go, :ride, :drive)), returning the shared KitRunResult instead of GoResult / RideResult / DriveResult.

execute!(:go, "job.jl", ["parent:2"]; args=["8"])
execute!(:ride, "job.jl", ["parent:2"])
execute!(:drive, "job.jl", ["parent:2"]; args=["8"])
wait(execute!(:go, "job.jl", ["parent:1"]; detached=true, args=["8"]))

output_dir, args, project, sync, julia are the keywords go! and drive! already share (ride! ignores sync). With detached=false (default), any other keyword is forwarded to the chosen function.

detached=true spawns julia -m DistSSHKit go|ride|drive and returns a KitProcess. --project= is always the job project= when that tree has a Project.toml. The job must list DistSSHKit or DistSSHRun in [deps]; otherwise this throws instead of using serve's active project. Keywords are then an allow-list (unknown names throw): output_dir, args, project, sync, julia, quiet, verbosity, yes, remote, hosts_file, job_id, source, allow_mismatch, and drive-only log_dir, enable_log, package, require_all_hosts, skip_hash_check, mem_headroom, parent_gb, workers, sync_script, allow_external_symlinks, dir, threads, env_allow, and env. source is a provenance dict for every kind. Detached passes it as DISTSSHKIT_SOURCE_*. Go-only repeat. Ride: spi_check (default false). Detached argv passes --spi-check when true and --no-spi-check when false, so an older child whose default is on still skips the compare. Neither go nor ride takes size! flags. yes must be true (the default): an unattended child cannot answer a prompt. remote that starts with ~ is stored in DISTRIBUTED_REMOTE_PROJECT_ROOT as a layout path (not expanduser on the kit parent). Child stdio defaults to kit.out / kit.err in run_dir. Pass stdout / stderr (IO) to override; stdout=stdout inherits the parent. Parent redirect_stdout does not apply to the subprocess. Detached :drive omits --output-dir unless output_dir= or inherited DISTRIBUTED_OUTPUT_DIR is set, so init_output_dir! can choose the artifact root.

job_id, if given, is passed to the child as DISTSSHKIT_JOB_ID, which adds job=<id> to every progress: log line. DISTSSHKIT_PROGRESS=1 is --progress verbosity, not a watcher; read lines with DistSSHRun.parse_progress_line / DistSSHRun.kit_progress_latest. Omitted entirely when unset.

The detached child starts in dir (default: the project directory) and passes --history-file=no. threads defaults to 1, passed as --threads=1 (Threads.nthreads(:interactive) is 0 on Julia 1.13). threads=:inherit passes this process's resolved --threads spec. threads=:unset omits the flag. The child environment keeps an allowlist (PATH, HOME, JULIA_DEPOT_PATH, DISTSSHKIT_*, DISTRIBUTED_*, and the other baseline names). env_allow adds names to that baseline. :all copies every non-empty parent variable except the drops below. env sets values on the child and does not write this process. Names containing COOKIE, JULIA_LOAD_PATH, and the CLI include guards are never copied. A recognized proxy value that contains userinfo (http_proxy, https_proxy, all_proxy, no_proxy, and the uppercase names) is dropped unless that name is in env_allow or env. A case-sensitive substring denylist (SECRET, PASSWORD, PASSWD, TOKEN, API_KEY, APIKEY, ACCESS_KEY, PRIVATE_KEY, CREDENTIAL) drops baseline, prefix, and :all copies. An explicit env_allow or env name wins and is recorded as sensitive. A count of dropped names is logged. The names, not the values, are in detached_launch, run.toml [launch], and the debug log (JULIA_DEBUG=DistSSHRun). schema stays 1.

Local go slots and local drive workers inherit that environment, including SSH_AUTH_SOCK when it was kept. SSH workers do not receive this process's agent socket. A drive --isolated grandchild inherits the filtered environment. In-process execute! and julia -m DistSSHKit do not use this policy.

execute!(kind, script, tokens; detached=true, dir=pwd(), threads=:unset, env_allow=:all)

That restore still drops JULIA_LOAD_PATH, the CLI include guards, names that contain COOKIE, names that contain a denylist substring, and a recognized proxy value that contains userinfo. Set a denylisted name or such a proxy value with env, or name it in an env_allow list. The list keeps the baseline and those names. It does not copy the rest of the parent environment. JULIA_LOAD_PATH, the CLI include guards, and names that contain COOKIE cannot be passed that way.

Reads DISTRIBUTED_SSH_OPTS live (not frozen at package precompile). Prefer this over a const so E2E / ProxyJump overrides apply in the same process.

DistSSHRun.DistSSHBase.shell_status — Function
shell_status(proc::Base.Process)::Int

Status of a child that has exited, using the shell's 128 + signal rule.

A signaled process (termsignal > 0) returns 128 + termsignal. Unix records that child as exitcode == 0 with success false. SIGINT is 130, SIGPIPE is 141, SIGKILL is 137, and SIGTERM is 143. Any other exit returns exitcode unchanged, including 0, 3, 127, and 255.

Throws ArgumentError when proc has not exited. Does not print, and does not fold a signal into 1 or 255.

DistSSHRun.identity_mismatches — Function
identity_mismatches(parent, other; allow=Symbol[], shipped_manifest="") -> Vector{String}

Same lines as go!, ride!, and drive!. An empty vector matches. This does not throw, print, or read DISTSSHKIT_QUIET.

:julia in allow skips both "version" and "commit". :distssh skips pkg.*. :manifest skips the Manifest path. Any other symbol does not throw and waives nothing. Parse a CLI list with parse_allow_mismatch.
