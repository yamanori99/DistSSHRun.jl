API

Exported names, grouped by the command they belong to. The longer guide is the DistSSHKit manual.

Run

go! runs a script as-is on one or more slots. drive! runs a driver script on workers. ride! is experimental: it rewrites map and filter in a script onto workers.

DistSSHRun.DetachedProcess — Type

Handle to a detached execute! child (detached=true).

process is the julia -m DistSSHKit go|drive|ride subprocess. run_dir is always allocated in the parent before spawn (pid / kit.out / run.toml). Read it with result_run_dir. The field is not API. output_dir is the artifact root when known at spawn (go / ride, explicit output_dir=, or inherited DISTRIBUTED_OUTPUT_DIR). Detached :drive without those leaves output_dir as nothing so the child can honor init_output_dir!. log_dir is nothing for :go / :ride. wait returns a DistSSHJobResult; it does not fill output_dir on this handle.

DistSSHRun.DistSSHJobResult — Type

Shared run outcome (ok, kind, dirs, failed_step, exit_code, hosts, stop).

kind is :go, :drive, :ride, or :pipeline. Convert with kit_run_result. hosts is post-run collect (HostRunResult); empty for go, hung wait, or a drive that never collected.

stop is the terminate! / terminate_run! ladder outcome. nothing on a run that was not stopped that way. :within_grace means one SIGINT was sent and the process was gone before SIGTERM, so workers had that interrupt_grace window. :sigterm and :sigkill mean that window ended and the ladder escalated. :no_sigint means interrupt_grace was 0, so SIGINT was not sent and the ladder went to SIGTERM (then SIGKILL if the process was still alive). The same string is stop in kit.result. When the kit run directory already has this package's run.toml, stop is set there too. schema stays 1. An unknown stop string is ignored.

run_dir is this run's DISTSSH_RUN_DIR when one is known. Read it with result_run_dir. result_provenance reads run.toml from it. result_content_tree_hash and result_remote_run_id read provenance.selection in that file. A RideResult is not accepted there; convert it with kit_run_result first.

Result fields and positional constructors are not API. Result structs are not a stable serialization format. serialize and JLD2 of a result are unsupported. The supported record is kit.result.

DistSSHRun.DriveResult — Type

Outcome of drive! (and similar CLI steps that return an exit code).

ok is true only when the run finished with exit 0. By default that includes the placement contract: listed parent / child hosts joined, stayed, and collect succeeded (best_effort=false, the default). best_effort=true keeps a partial run as ok=true.

output_dir / log_dir are the directories actually used for this run — resolved the same way drive reports Results: / writes its log, even when drive! was not called with output_dir= / log_dir=. nothing when no real run happened (e.g. built by hand) or, for log_dir, when logging was disabled.

hosts is one HostRunResult per host that joined as a worker, in the order results were collected. Empty when no host-collection step ran (e.g. built by hand, or a run with no remote/local-only hosts).

run_dir is this run's DISTSSH_RUN_DIR when the driver allocated one. Read it with result_run_dir. result_provenance reads run.toml from it. result_content_tree_hash and result_remote_run_id read provenance.selection in that file.

Result fields and positional constructors are not API. Result structs are not a stable serialization format. serialize and JLD2 of a result are unsupported. The supported record is kit.result.

DistSSHRun.drive! — Method
drive!(session::DistSSHSession, script; plan=nothing, args=[], ...)
drive!(script, workers...; kwargs...)
drive!(script, workers::AbstractVector; kwargs...)

Run a driver script on workers. Tokens match the CLI (parent:2, 1*user@host). Load is the master include. Publish sends definitions to workers (not top-level work). Run is main() when defined. Use go! / ride! when that matches the script.

drive!("job.jl", "parent:2"; args=["8"])
drive!(session, "job.jl")  # uses `session.tokens`

With sync omitted or false (the default), prepare remotes with setup! or CLI setup first; remotes are checked before execution. The drive CLI does not take --ship-tree or --git-sync; prepare with setup ship-tree or setup git-sync, then setup instantiate when needed, then drive --run-id ID. Passing sync=:git_sync or sync=:ship_tree on drive! is an ArgumentError (transfer on run was removed). Git parity is off by default (skip_hash_check=true). By default (best_effort=false) every listed host must join and load workers, stay through the run, and collect must succeed; otherwise the run fails with a LaunchReport. Pass best_effort=true or CLI --best-effort for a partial run.

A collect root that is the project or a parent of it stops the run before main and before collect, with exit code 1. That includes DISTRIBUTED_COLLECT_DIRS and a default root from DISTRIBUTED_OUTPUT_DIR.

julia sets the remote Julia binary (nothing / "auto" → detect; same as CLI --julia). run_id (CLI --run-id) selects runs/<ID>/src under the deploy root when sync is omitted or false. plan is an optional explicit WorkerPlan. pipeline! runs drive! and optional collect only; call setup! first. It does not pass run-time sync= into drive!.

worker_include=true (CLI --worker-include) re-includes the full driver on workers. The default publishes definitions / using / import / include only, so top-level work on Load is not repeated on workers.

Ctrl-C restores the active project and the DISTRIBUTED_* entries this call changed, then rethrows InterruptException or, when Julia has it, Base.CancellationRequest. drive! does not exit and does not throw the private CLI exception. With Base.CANCEL_TOKEN, the caller's task may stay cancelled after that exception.

DistSSHRun.go! — Method
go!(script, workers...; kwargs...)
go!(script, workers::AbstractVector; kwargs...)

Run an as-is complete job on one or more slots (local and/or remote).

[provenance] records this controller under julia.parent and machine.parent. Each slot that ran the script is under workers, grouped by placement token. The manifest hash and the git snapshot are taken when go! starts.

go!("job.jl")                          # one parent slot
go!("job.jl"; repeat=100)              # 100 independent runs on parent
go!("job.jl", "parent:2"; args=["8"])
go!("job.jl", "1*user@h1", "1*user@h2"; remote="/path/to/project")

Each slot gets DISTRIBUTED_OUTPUT_DIR pointing at {script}/.distssh/go/<stem>_<UTC>/<slot>/. Override the batch root with output_dir (CLI: --output-dir). For backward compatibility collect_spec::AbstractString also sets the batch root, but passing both output_dir and collect_spec::String is an error. collect_spec === false means "skip collect" and is orthogonal to output_dir.

Default sync is false (no pre-run sync; remotes are checked first — setup is assumed done). The go CLI does not take --ship-tree or --git-sync; prepare with setup ship-tree or setup git-sync, then setup instantiate when needed, then go --run-id ID. Passing sync=:git_sync or sync=:ship_tree on go! is an ArgumentError. run_id (CLI --run-id) selects runs/<ID>/src when sync is omitted or false. A script outside the project is allowed with run_id when that ship used extra_files=[script]. The remote command is remote_script_path: _distsshrun_external/<basename> under the selected project directory. run_id also skips the in-tree [sources] check: a sibling path dependency was already shipped. go! has no git-parity gate; use drive! with skip_hash_check=false (CLI: drive --require-git) when you need that.

julia sets the Julia binary for each slot (nothing / "auto" → detect; same as CLI --julia).

unsafe_skip_env_digests (CLI --unsafe-skip-env-digests) waives only Manifest and Project byte digest checks across slots (recorded as unverified). Julia build and DistSSH* Manifest version strings must still match. Digest comparison is byte-exact (CRLF differences count).

When workers is empty and hosts_file is omitted, DISTSSH_HOSTS_FILE is still read (API go!("job.jl")). Non-empty workers (CLI host_tokens) does not re-read that ENV.

head_slots (CLI --head-slots N) adds N local subprocess runs on this machine. N*host tokens add SSH full-script runs. Together they start in one batch. repeat=N (CLI --repeat N) is the total number of those runs, spread round-robin across listed hosts and local slots. Without repeat, every host token needs an explicit N* count and at least one slot must be configured (head_slots and/or remotes). path_anchor shortens displayed paths (CLI passes kit project root).

DistSSHRun.terminate! — Method
terminate!(kp::DetachedProcess; grace=10, interrupt_grace=nothing) -> DistSSHJobResult

Stop a detached run. Omit interrupt_grace and the wait is 30 seconds, or DISTSSH_WAIT_SIGINT_GRACE when that variable is set in this process. The driver host does not read it. An explicit interrupt_grace keyword wins, including 0, which sends no SIGINT. A negative value or NaN is an error. The 30 second default is a constant, chosen from the internal stop budgets, not computed when terminate! runs.

A positive value sends SIGINT once and waits that many seconds. There is no retry. A drive child runs its Ctrl-C path: one kill -INT per SSH host, aimed at the worker julia pid (WorkerConfig.ospid, the worker's getpid()), then a fixed 3 second settle, then rmprocs. That ssh is bounded by the SSH connect timeout and uses ServerAliveInterval=5 and ServerAliveCountMax=1. A write during the settle window is best-effort and should be small. Checkpoint large state during the run, to a temporary file, then rename it. A 1 GiB write in 0.4–0.7 seconds on one Mac mini is a lower bound. On Julia 1.13 a second Ctrl-C forces the driver out of that cleanup. On Julia 1.13, a driver waiting in pmap ignores SIGINT, so this wait runs out and SIGTERM stops it. With the defaults that is 30 seconds plus grace (10) plus one second after SIGKILL, about 41 seconds, and then the tagged pkill below. A process-group SIGINT, as from a terminal Ctrl-C, also misses that path on Julia 1.13: the driver exits 1 and does not send kill -INT. Measured on macOS. On builds without Base.CANCEL_TOKEN (e.g. 1.13 and 1.14.0-beta1 through 1.14.x) the driver exits 130, but a worker can be removed before it sees the interrupt. A go or ride child is julia -m with exit-on-sigint, so SIGINT runs atexit and does not enter catch or finally. Then SIGTERM, wait up to grace seconds (0 sends SIGTERM and does not wait), then SIGKILL if the process is still alive. Then pkill only processes tagged with this run's job_id (from kit.job), never julia.*--worker. Without job_id, only the child is signaled. That pkill is one SSH command per host, in parallel, deduplicated, with its own 15 second bound (SSH connect plus margin). It does not spend interrupt_grace. Worst case for those two stages is interrupt_grace plus that bound. pkill exit 1 means nothing matched and is success. Hosts that cannot be reached are named in one warning, and this still returns. The remote pattern is [d]istsshkit-job:…, so pkill -f does not match the sh -c line that contains the command.

The returned DistSSHJobResult stop is that ladder outcome. The same string is written to kit.result. When run_dir holds this package's run.toml (schema = 1, writer starting with DistSSHRun), stop is set there too. Artifact output_dir / log_dir are not rewritten.

Base.wait — Method
wait(kp::DetachedProcess; timeout=nothing) -> DistSSHJobResult

Block until the detached child exits, then return a DistSSHJobResult.

Does not mutate kp.output_dir / kp.log_dir. After a detached :drive that deferred the artifact leaf, read the returned result (or kit_result_from_dir / read_kit_run_toml on the directory from result_run_dir).

timeout is wall-clock seconds until the child process exits (not the drive worker heartbeat). nothing waits forever. On timeout the child is left running: failed_step is "hung", exit_code is 124, and owned stdio stays open. Call terminate! if the hang is fatal.

If the child wrote kit.result under run_dir or output_dir, that file is the source of truth (including failed_step from go! / ride!). Otherwise failed_step is "go" / "ride" / "drive" on a non-zero exit — the parent cannot recover a more specific in-process step name.

Best-effort: remove kit.pid if it still names this child (pid captured before wait on the OS process; after reap getpid can throw ESRCH). Not on a hung timeout.

DistSSHRun.collect! — Method
collect!(
    session::DistSSHSession,
    local_root::AbstractString;
    merge=false,
    best_effort=false,
    hosts=nothing,
    julia=nothing,
    remote_root=nothing,
)

Pull result files from SSH hosts into local_root with stdlib Tar. Remote mtimes are not kept. A non-executable file arrives as mode 0644, and an executable file as 0755. A symlink that points outside the copied tree is refused. julia is the remote executable (nothing auto-detects).

  • merge=true → collect-overwrite (CLI drive --collect-overwrite)

DistSSHRun.execute! — Function
execute!(kind, script, tokens=String[]; output_dir=nothing, args=String[], project=pwd(), sync=nothing, julia=nothing, detached=false, source=nothing, kwargs...) -> DistSSHJobResult or DetachedProcess

One seam over go! / ride! / drive! for callers that pick the kind at runtime (kind ∈ (:go, :ride, :drive)), returning the shared DistSSHJobResult instead of GoResult / RideResult / DriveResult.

execute!(:go, "job.jl", ["2*host1"]; head_slots=2, args=["8"])
execute!(:ride, "job.jl", ["2*host1"]; head_workers=2)
execute!(:drive, "job.jl", ["2*host1"]; head_workers=2, args=["8"])
wait(execute!(:go, "job.jl", ["1*host1"]; detached=true, head_slots=1, args=["8"]))

output_dir, args, project, sync, julia are the keywords go! and drive! already share (ride! ignores sync). With detached=false (default), any other keyword is forwarded to the chosen function.

detached=true spawns julia -m DistSSHKit go|ride|drive and returns a DetachedProcess. sync=:ship_tree or sync=:git_sync is an error before spawn (run no longer transfers). Ship or git-sync first with setup! :ship_tree / :git_sync, or CLI setup ship-tree / setup git-sync. A script outside the project is extra_files=[script] (one file, at _distsshrun_external/<basename>), then setup!(session, :instantiate; run_id=id), then execute!(...; run_id=id) with that same local script. In-process go! / drive! reject sync=:ship_tree and sync=:git_sync the same way. Omitted/false sync and run_id= are unchanged. --project= is always the job project= when that tree has a Project.toml. The job must list DistSSHKit or DistSSHRun in [deps]; otherwise this throws instead of using serve's active project. Keywords are then an allow-list (unknown names throw): output_dir, args, project, sync, julia, quiet, verbosity, yes, remote, hosts_file, job_id, source, unsafe_skip_env_digests, and drive-only log_dir, enable_log, package, best_effort, skip_hash_check, workers, worker_include, allow_external_symlinks, dir, threads, env_allow, and env. source is a provenance dict for every kind. Detached passes it as DISTSSH_SOURCE_*. Go-only repeat. Ride: spi_check (default false). Detached argv passes --spi-check when true and --no-spi-check when false, so an older child whose default is on still skips the compare. Neither go nor ride takes sizing flags. yes must be true (the default): an unattended child cannot answer a prompt. remote that starts with ~ is stored in DISTRIBUTED_REMOTE_PROJECT_ROOT as a layout path (not expanduser on the kit parent). Child stdio defaults to kit.out / kit.err in run_dir. Pass stdout / stderr (IO) to override; stdout=stdout inherits the parent. Parent redirect_stdout does not apply to the subprocess. Detached :drive omits --output-dir unless output_dir= or inherited DISTRIBUTED_OUTPUT_DIR is set, so init_output_dir! can choose the artifact root.

job_id, if given, is passed to the child as DISTSSH_JOB_ID, which adds job=<id> to every progress: log line. DISTSSH_PROGRESS=1 is --progress verbosity, not a watcher; read lines with DistSSHRun.parse_progress_line / DistSSHRun.kit_progress_latest. Omitted entirely when unset.

The detached child starts in dir (default: the project directory) and passes --history-file=no. threads defaults to 1, passed as --threads=1 (Threads.nthreads(:interactive) is 0 on Julia 1.13). threads=:inherit passes this process's resolved --threads spec. threads=:unset omits the flag. The child environment keeps an allowlist (PATH, HOME, JULIA_DEPOT_PATH, DISTSSH_*, DISTRIBUTED_*, and the other baseline names). env_allow adds names to that baseline. :all copies every non-empty parent variable except the drops below. env sets values on the child and does not write this process. Names containing COOKIE, JULIA_LOAD_PATH, and the CLI include guards are never copied. A recognized proxy value that contains userinfo (http_proxy, https_proxy, all_proxy, no_proxy, and the uppercase names) is dropped unless that name is in env_allow or env. A case-sensitive substring denylist (SECRET, PASSWORD, PASSWD, TOKEN, API_KEY, APIKEY, ACCESS_KEY, PRIVATE_KEY, CREDENTIAL) drops baseline, prefix, and :all copies. An explicit env_allow or env name wins and is recorded as sensitive. A count of dropped names is logged. The names, not the values, are in detached_launch, run.toml [launch], and the debug log (JULIA_DEBUG=DistSSHRun). schema stays 1.

Local go slots and local drive workers inherit that environment, including SSH_AUTH_SOCK when it was kept. SSH workers do not receive this process's agent socket. A drive --isolated grandchild inherits the filtered environment. In-process execute! and julia -m DistSSHKit do not use this policy.

execute!(kind, script, tokens; detached=true, dir=pwd(), threads=:unset, env_allow=:all)

That restore still drops JULIA_LOAD_PATH, the CLI include guards, names that contain COOKIE, names that contain a denylist substring, and a recognized proxy value that contains userinfo. Set a denylisted name or such a proxy value with env, or name it in an env_allow list. The list keeps the baseline and those names. It does not copy the rest of the parent environment. JULIA_LOAD_PATH, the CLI include guards, and names that contain COOKIE cannot be passed that way.

DistSSHRun.DistSSHBase.shell_status — Function
shell_status(proc::Base.Process)::Int

Status of a child that has exited, using the shell's 128 + signal rule.

A signaled process (termsignal > 0) returns 128 + termsignal. Unix records that child as exitcode == 0 with success false. SIGINT is 130, SIGPIPE is 141, SIGKILL is 137, and SIGTERM is 143. Any other exit returns exitcode unchanged, including 0, 3, 127, and 255.

Throws ArgumentError when proc has not exited. Does not print, and does not fold a signal into 1 or 255.

Identity

run_identity and identity_mismatches are public and are not exported. go!, ride!, and drive! require the same Julia build (version and commit) and DistSSH* pkg.* versions on every worker or go slot. They also compare resolved Manifest and Project file SHA-256 digests (byte-exact; CRLF differences count) when the controller has an active Manifest. Without a controller Manifest digest, launch fails before workers join unless you pass CLI --unsafe-skip-env-digests, which waives only Manifest/Project digest checks (recorded as unverified; Julia build and DistSSH* versions must still match). A Julia whose Base.GIT_VERSION_INFO.commit is empty (some source builds and distribution builds) cannot run DistSSH multi-host jobs: an unknown commit is a mismatch by design, and --unsafe-skip-env-digests does not waive it. Add DistSSHKit. These names are not a command.

identity_mismatches(parent, other; unsafe_skip_env_digests=false) -> Vector{String}

Same lines as go!, ride!, and drive!. An empty vector matches. This does not throw, print, or read DISTSSH_QUIET.

Julia version and commit (Julia build), the resolved sysimage path, and DistSSH* pkg.* versions from the Manifest are always compared. An empty or missing commit on either side is a mismatch.
