- A declared input with hashing on is recorded as `sha256-manifest-v1` under `DISTSSHKIT_RUN_DIR/inputs/<sha256>.manifest`. The file name is the SHA-256 of `ncodeunits(name):name` plus a newline and the host, so two different name/host pairs do not share a path. Each line is `hex *path`. A regular file contributes the SHA-256 of its bytes. A symlink contributes the SHA-256 of its link text and is not followed, so `sha256sum -c` does not check that line. A declared path that is a symlink to a file is recorded as that link. A link target with a tab or newline is refused, including when the declared path itself is a symlink. A path with a backslash is refused in `inputs.toml` and in manifest entries. `check_input_manifest(manifest, root)` checks both and resolves each path component by NFC form when the filesystem kept NFD; `sha256sum -c` opens paths literally. Paths are relative to the declared root, NFC, separated by `/`, and sorted in byte order. A file input is one line whose path is that file's basename. `run.toml` `inputs` lists `name`, `path`, `host`, `algorithm`, `content_hash`, `files`, `bytes`, `verification`, and `hashed_at`. A later ship into the same run directory replaces the row for the same name and host. `hash = false` sets `verification` to `stat`, omits `content_hash`, records `newest_mtime` and `stat_digest`, and does not write a `.manifest`. Ship prints `hashed <name>: <size> in <seconds> s`. Content hashing also prints progress and a remaining-time estimate. `ship-tree` refuses a repeated host.
