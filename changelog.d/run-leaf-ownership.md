category: breaking

- Ship writes a minimal `run.toml` under each remote `runs/<run_id>/` with `schema`, `writer`, and `kind = "ship"` only. `setup --delete` refuses a Ship leaf whose `run.toml` is present but not DistSSHRun-owned, including when that path contains a newline, the entry is a symlink or other non-regular file, or the text has an unclosed quote or bracket. It also refuses when `runs` itself is a symlink (including a dangling link), or when an entry directly under `runs/` is a symlink. The check is the deploy root's `runs/<run_id>/run.toml` when that deploy root is the confirmed delete path or a descendant of it, including when the confirmed path is a git-work-tree ancestor. `setup --prune` applies the same check to `.distsshkit` candidates (including nested stamps under a candidate). A remote stamp written by `TOML.print` (`[[inputs]]`, `[provenance.git]`, quoted table names) is owned; duplicate top-level `schema` / `writer` / `kind` lines are not. Local prune refuses a FIFO, directory, symlink, or other non-regular `run.toml` without opening it. A traversal error during that walk aborts prune instead of skipping an unreadable nested directory. Remote prune inspects every selected leaf before any `rm`. A missing file (older trees) still uses structural checks only. A failed write of the remote ownership checker, or of the file that records an unowned stamp, is treated as unowned. Remote `setup --prune` also refuses when a path to `.distsshkit` contains a newline, or when a selected leaf under `go/` or `runs/` does, so that line-oriented walk cannot prune a prefix of the path. A failed `.distsshkit` walk (permissions or `find` status) is reported as a scan failure, not as a newline.
