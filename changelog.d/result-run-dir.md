- `DriveResult`, `GoResult`, `RideResult`, and `KitRunResult` carry `run_dir`. Omitted values stay `nothing`, so existing positional calls still construct. A seven-argument `GoResult` still takes `failed_step` in that position and fills `run_dir` from the active `DISTSSHKIT_RUN_DIR`. `go!` and `ride!` do the same. `ride!` keeps that directory on `RideResult` after it restores the previous `DISTSSHKIT_RUN_DIR`. `drive!` returns the directory that run allocated. `result_run_dir` is the public read of that directory. `result_provenance` reads `run.toml` for a `DriveResult`, `GoResult`, or `KitRunResult`. A `RideResult` goes through `kit_run_result` first. Result fields and positional constructors are not API, and `serialize` / JLD2 of a result is unsupported. `kit.result` records `run_dir` when one is known.
