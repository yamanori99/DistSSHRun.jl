category: breaking

- `--ship-tree` no longer needs a git work tree and does not run git. The send list walks the project directory that was passed, not the workspace Manifest directory, and applies each `.gitignore` there and below (case-sensitive; `core.ignorecase` is not used), including inside a nested `.git`. `.git/info/exclude`, `core.excludesFile`, and a `.gitignore` above that directory are not used. A Manifest or path dependency outside that directory is left out with a warning. An absolute `[sources]` path is still an error. `ShipTreeResult.tree_matches_head` is `nothing` because the tar is not compared to a git tree. Schema 1 `run.toml` does not carry that field. A gitignored `Project.toml`, `JuliaProject.toml`, `Manifest.toml`, or `JuliaManifest.toml` is an error; pack does not ship the tree. A gitignored `LocalPreferences.toml` is not added back; add `!LocalPreferences.toml` to ship it. Declared inputs stay out. `rsync_send_list`, `--clone`, `--sync`, and `--pull` stay on git. `go` still resolves `env_dir` from the Manifest. A file over 50 MiB, or a send list over 100 MiB, prints a warning and still ships. `DISTSSH_SHIP_WARN_FILE_BYTES` and `DISTSSH_SHIP_WARN_TOTAL_BYTES` set those limits (non-negative integers; an invalid value is an error). The warning lists the largest files and directories from local sizes. The 256 MiB cap still throws.
